# bridge-guide

「시설물의 안전 및 유지관리 실시 세부지침(**안전점검·진단 편**) **교량편**」
2022 / 2023 / 2024 / 2026 판본 질의응답 웹 도구.

---

## 왜 필요한가

미국 FHWA가 현직 교량점검자 49명에게 같은 교량을 점검시킨 연구(FHWA-RD-01-020)에서,
주요 부재 하나당 **평균 4~5개의 서로 다른 등급**이 매겨졌고 평균 ±1점 이내에 든 판정은 68%뿐이었다.
지침서를 못 찾아서가 아니라, 찾아 읽고도 다르게 판정하기 때문이다.

이 저장소는 그 변동성을 줄이는 것을 목표로 한다. 핵심은 하나다:

> **등급은 파이썬 코드가 판정하고, AI는 그 결과를 문장으로 옮기기만 한다.**

같은 값을 물으면 언제나 같은 등급이 나오고, 모든 답에 (연도판, 표번호, 면)이 붙는다.

---

## 설치와 실행

파이썬 3.10 이상이 필요하다. 그 외 필수 의존성은 없다.

```bash
git clone https://github.com/bonhyungu-png/bridge-guide.git
cd bridge-guide
python 서버.py
```

`http://127.0.0.1:8765/`가 열린다. 그 화면에 그냥 자연어로 물으면 된다.

```
콘크리트 바닥판 균열폭 0.25mm면 몇 등급이야?
표1.31이 2024년이랑 2026년이랑 같은 표야?
선택과업은 언제 실시해?
```

준비가 됐는지 먼저 보고 싶으면:

```bash
python 서버.py --doctor
```

### 답을 만들 AI

이 컴퓨터에 **이미 있는 것**을 빌려 쓴다. 둘 중 하나만 있으면 된다.

| 방법 | 필요한 것 | 비용 |
|---|---|---|
| **Claude Code** (기본) | 설치하고 로그인만 | 이미 낸 구독을 그대로 쓴다 |
| API 키 | `ANTHROPIC_API_KEY` · `GEMINI_API_KEY` · `OPENAI_API_KEY` 중 하나 | 키에 요금이 붙는다 |

```bash
python 서버.py --engines          # 쓸 수 있는 것 확인
python 서버.py --engine anthropic-api   # 직접 고르기
```

**MCP를 따로 등록할 필요는 없다.** 서버가 AI를 부를 때마다 도구를 직접 물려
준다(`claude --mcp-config`). 예전에는 등록을 사용자에게 맡겼는데, 안 돼 있으면
도구 없이 답이 나왔고 그걸 알아채기도 어려웠다.

> 답 아래 원본 PDF 쪽을 그림으로 띄우려면 `pip install pdfplumber`가 필요하다.
> 없으면 답은 그대로 나오고 그림만 안 뜬다.

## 답하는 곳은 웹 하나뿐이다

예전에는 터미널·MCP 플러그인·Cursor·Codex·아티팩트까지 여러 창에서 답할 수
있었다. 그런데 창마다 도구가 붙었는지 안 붙었는지가 달랐고, 웹앱에는 도구가
JS로 한 벌 더 복사돼 있었다. 그래서 **같은 질문에 창마다 다른 답**이 나왔다 —
실제로 "콘크리트"로 표를 검색하면 터미널과 웹이 6개 중 1개만 겹쳤다.

지금은 답하는 자리가 하나다. 도구 구현도 `bridgekb` 하나다.

```
브라우저 ──POST /ask──► 서버.py ──► engines.py ──► Claude Code (도구를 물려서)
                          │                        또는 API 3종 (도구 루프를 직접)
                          │                                  │
                          └──────────────────────────────────┴──► bridgekb.tools
                                                                   도구 6개, 단일 구현
```

`bridgekb/mcp_server.py`는 남아 있지만 **내부 배선**이다 — 서버가 빌려 온
Claude에게 도구를 건네는 통로일 뿐, 사용자가 등록하거나 신경 쓸 것이 아니다.

### 도구 6개

| 도구 | 하는 일 |
|---|---|
| `list_members` | 그 판본의 부재·지표 목록 |
| `grade_lookup` | 부재·지표·값 → **등급 + 근거 원문 + 출처**. 등급이 정해지는 유일한 자리 |
| `qualitative_criteria` | 서술형(정성) 기준. 등급을 확정하지 않고 후보만 준다 |
| `table_lookup` | 표 번호·제목 검색 + 연도별 번호 밀림 경고 |
| `table_content` | 표 하나의 실제 내용 |
| `body_search` | 본문 문단 검색 |

## 설계 원칙

1. **사실은 코드가, 문장은 AI가.** 등급 판정·표 조회는 전부 파이썬이 한다.
   비용 때문이 아니라 **재현성** 때문이다.
2. **출처 없는 사실 문장을 쓰지 않는다.** 모든 답에 (연도, 표번호, 면수)를 붙인다.
3. **애매하면 고르지 않고 되묻는다.** "교면포장"은 시멘트와 아스팔트가 서로
   다른 표이고 등급도 다르다. 하나를 골라 답하면 틀렸다는 걸 아무도 알 수 없다.
4. **모르는 연도는 바꿔치기하지 않는다.** 2021년을 물으면 없다고 답한다.
5. **답하는 곳은 하나.** 구현이 둘이면 언젠가 갈라진다.
6. **AI 회사에 매이지 않는다.** Claude Code든 API 키든 있는 것을 쓴다.

## 구조

```
bridge-guide/
├── 서버.py               ★ 유일한 진입점 - 웹 화면 + /ask + 출처 PDF 쪽 렌더링
├── webapp/
│   └── bridge_guide.html   웹 화면 (단일 파일, 빌드 불필요)
├── bridgekb/             ★ 조회 엔진 - AI를 모른다
│   ├── tools.py            ★ 도구 6개 - 유일한 구현
│   ├── kb.py               판정규칙 적재, 이름 맞추기, 구간 판정
│   ├── anchor.py           표 조회 (연도별 번호 밀림 흡수)
│   ├── engines.py          질문을 보낼 AI 고르기
│   ├── mcp_server.py       내부 배선 - 빌려 온 AI에게 도구를 건넨다
│   ├── pdfnorm.py          원본 PDF 좌표계 맞추기 (빌드용)
│   └── config.py           경로 단일 창구
├── bridge_mcp.py         MCP 진입점 (서버가 --mcp-config 로 물린다)
├── data/                 ★ 정본·파생 + 원본 PDF
├── knowledge/            표 → PDF 쪽 지도 (빌드 산출물)
├── build/                빌드 파이프라인 (정본을 다시 만들 때만 쓴다)
│   ├── 16_출처페이지매핑.py     표 → 실제 PDF 쪽 찾기
│   └── 17_페이지값_보정.py      찾은 쪽을 데이터에 박기
└── tests/                pytest
```
