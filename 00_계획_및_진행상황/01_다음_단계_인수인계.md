## 2. 막힌 것 — 플러그인 배포는 실패했다

`/bridge-guide` 슬래시 명령으로 GUI를 띄우려 했으나 **끝내 동작시키지 못했다.**
원인을 파고들며 알아낸 것들(다음에 같은 함정에 빠지지 않도록 기록):

1. **플러그인 캐시는 `version`으로 키잉된다.**
   `~/.claude/plugins/cache/bridge-guide/bridge-guide/0.1.0/`에 캐시되고,
   `installed_plugins.json`이 **설치 시점의 `gitCommitSha`에 고정**된다.
   `plugin.json`의 version을 안 올리면 GitHub에 아무리 push해도
   **반영되지 않는다.** → 0.2.0으로 올려놨으니 다음엔 재설치하면 받아온다.
   **앞으로 플러그인 내용을 고칠 때마다 version을 반드시 올릴 것.**

2. **커맨드와 스킬이 같은 이름이면 충돌한다.**
   `commands/bridge-guide.md`와 `skills/bridge-guide/SKILL.md`가 둘 다
   "bridge-guide"였다. 스킬 쪽 frontmatter `name`을 `bridge-guide-answer`로
   바꿔 분리해뒀다.

3. **환경마다 지원 범위가 다르다.**
   Claude 데스크톱 앱에서는 `/plugin` 자체가 없다. 터미널 CLI에서는
   되지만 캐시 문제로 구버전이 계속 실행됐다.

4. **`/bridge-guide` 같은 슬래시 명령은 환경 간 표준이 없다.**
   Claude Code·Cursor·Gemini CLI가 각각 다른 문법을 쓴다.
   **"모든 환경에서 똑같은 슬래시 명령"은 원리적으로 불가능하다.**

정리 작업: stale 캐시와 설치 기록을 직접 삭제해뒀다
(`~/.claude/plugins/installed_plugins.json.bak-*`에 백업 있음).

## 3. 정해진 방향 — MCP 서버 + GitHub Pages

### 왜 이 방향인가

원하는 것은 "**어디서 쓰든 같은 환경, 자유로운 자연어 질문**"이었다.
검토 결과 핵심은 이거였다:

> **서버를 띄우는 것(화면 보여주기)과 답을 만드는 것(AI 호출)은 다른 일이다.**
> FastAPI를 띄워도 답은 결국 AI가 해야 하고, AI를 부르려면 API 키가 필요하다.
> 키 없이 자유질문이 되는 길은 두 가지뿐이다:
> (a) 컴퓨터에 로컬 LLM 설치, (b) **사용자가 이미 쓰는 AI가 답하게 하기**

(b)가 **MCP**다. Cursor 쓰는 사람은 이미 GPT를, Claude Code 쓰는 사람은 이미
Claude를 쓰고 있으므로, 그 AI가 우리 도구를 집어 쓰게 하면
**우리 쪽 키도 서버 비용도 0원**이다.

MCP는 2025년 12월 Linux Foundation으로 이관돼 **벤더 중립 표준**이 됐고,
현재 Anthropic·OpenAI·Google·Microsoft·Cursor·VS Code가 모두 지원한다.

### 최종 구성

| 무엇 | 어떻게 | 비용 |
|---|---|---|
| **자유질문** | MCP 서버 — 각 환경에 한 번 등록하면 그 환경의 AI가 답함 | 0원 |
| **화면(GUI)** | GitHub Pages — 링크 하나, 로그인·설치 없음, 폰도 됨 | 0원 |

이러면 Claude 아티팩트도, 플러그인도 없어도 된다.

### 감수해야 할 것

MCP는 "명령어"가 아니라 "도구"다. 각 환경에서 `/bridge-guide`를 치는 게 아니라
**그냥 자연어로 물으면** AI가 알아서 우리 도구를 집어 쓴다.
오히려 환경 간 차이가 없어져서 이쪽이 더 낫다고 판단했다.

## 4. 다음에 할 일

### 4.1 MCP 서버 만들기 (제일 먼저)

**로직은 이미 다 있다.** `webapp/템플릿.html`의 `TOOLS` 배열에 도구 6개가
JS로 구현돼 있고 동작 검증도 끝났다. 이걸 파이썬 MCP 서버로 옮기면 된다.

옮길 도구 6개 (JS 구현이 그대로 명세 역할을 한다):

| 도구 | 하는 일 |
|---|---|
| `list_members` | 연도별 부재·지표 목록 (이름 매핑용) |
| `grade_lookup` | 부재·지표·값 → 등급 + 원문 + 출처. **등급 계산은 코드가 한다** |
| `qualitative_criteria` | 부재의 정성 기준 목록 (등급 확정 금지, 후보만) |
| `table_lookup` | 표 번호/제목 검색 + 연도별 번호 밀림 경고 |
| `table_content` | 표 하나의 실제 내용 |
| `body_search` | 본문 문단 검색 |

- 데이터는 `연구_2/data/파생/` 그대로 읽으면 된다
  (`bridgekb/anchor.py`가 이미 같은 구조를 읽고 있으니 재활용)
- 판정 로직은 `DB/스크립트/06_판정.py`의 `만족()`이 이미 같은 일을 한다
- 시스템 지시문(등급 직접 계산 금지, 출처 필수 등)은
  `webapp/템플릿.html`의 `RULES` 문자열을 그대로 쓰면 된다
