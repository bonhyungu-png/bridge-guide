## 2. 이번에 끝낸 것 — MCP 서버 (인수인계 4.1 · 4.3)

### 만든 것

| 파일 | 하는 일 |
|---|---|
| `bridgekb/kb.py` | 판정규칙 jsonl·본문 적재, 부재/지표 이름 맞추기, 구간 판정(`satisfies`) |
| `bridgekb/tools.py` | **도구 6개 + 행동 지침(`SYSTEM_RULES`)**. MCP·CLI·웹앱이 공유하는 유일한 구현 |
| `bridgekb/mcp_server.py` | MCP stdio 서버 (JSON-RPC 2.0) |
| `bridge_mcp.py` | 어느 폴더에서 실행해도 되는 진입점 (설정 파일에 절대경로 하나만 적으면 됨) |
| `.mcp.json` | 이 저장소를 열었을 때 Claude Code가 자동 등록 |
| `tests/test_tools.py` · `tests/test_mcp_server.py` | 회귀 테스트 30개 |

`python -m bridgekb` 에 `grade` · `search` · `tools` · `mcp` 서브커맨드를 붙였다
(`grade`·`search`는 MCP와 **같은 함수**를 부른다 — 창만 다르고 답은 같다).

### 설계에서 지킨 것

1. **의존성 0.** MCP stdio 전송은 줄바꿈으로 구분된 JSON-RPC 2.0일 뿐이라
   표준 라이브러리만으로 짰다. `pip install mcp`가 필요 없다 —
   "설치 없이 파이썬만 있으면 돈다"는 이 프로젝트의 전제와 같은 이유다.
2. **웹앱 JS와 같은 출력 키.** `webapp/템플릿.html`의 `TOOLS` 배열이 먼저 만들어진
   구현이자 명세다. 파이썬 쪽도 같은 이름·같은 입력·**같은 영어 출력 키**를 쓴다.
   브라우저에서 물어도 Cursor에서 물어도 같은 답이 나와야 하기 때문이다.
   (`anchor` 도구만 한글 키를 쓴다 — 먼저 만들어진 것이라 그대로 뒀다.)
3. **등급이 정해지는 자리는 `grade_lookup` 하나.** 서버가 접속할 때
   `instructions`로 "등급을 직접 계산하지 말 것"을 실어 보낸다.
4. **stdout은 프로토콜 전용.** 진단 문구는 전부 stderr로 간다.

### 윈도우에서 걸렸던 함정 (다음에 같은 데서 안 막히도록)

**stdout을 텍스트 모드로 쓰면 프로토콜이 깨진다.** 윈도우는 `\n`을 `\r\n`으로
바꾸고 콘솔 기본 인코딩이 cp949라 한글에서 `UnicodeEncodeError`가 난다.
그래서 `mcp_server._write()`는 `sys.stdout.buffer`에 **바이트로 직접 쓴다.**
`tests/test_mcp_server.py`가 서브프로세스를 띄워 이걸 검증한다 — 함수를 직접
부르는 테스트로는 이 경계가 안 잡힌다.

CLI 쪽도 같은 이유로 `main()`에서 stdout을 UTF-8로 재설정한다.

### 검증

```
47 passed in 27.37s
```

실제 클라이언트처럼 stdio로 붙어서 확인한 것:
initialize 핸드셰이크 · tools/list 6개 · tools/call · 알림 무응답 ·
없는 도구는 `isError`(프로토콜 오류가 아니라) · 없는 메서드는 `-32601` ·
깨진 JSON을 만나도 서버가 안 죽음 · stdout에 CRLF·비JSON 없음.

값 검증: **균열폭 0.25mm → b등급, [표 1.11] 1-27면** — SKILL.md 예시,
웹 GUI, CLI, MCP가 전부 같은 값을 낸다.

## 3. 다음에 할 일

### 3.1 GitHub Pages 배포 — **사람 손이 필요하다** (가장 먼저)

파일은 다 준비해 뒀다(`index.html` 리다이렉트, `.nojekyll`). 남은 것은
GitHub 쪽 작업인데 **이 로컬 저장소에 remote가 없다** (`git remote -v`가 비어 있고
`gh` CLI도 설치돼 있지 않다). 그래서 다음 두 가지는 사람이 해야 한다:

1. remote 연결 후 push
   ```bash
   git remote add origin https://github.com/bonhyungu-png/bridge-guide.git
   git push -u origin main
   ```
2. GitHub 저장소 → Settings → Pages → Source를 `main` 브랜치 `/ (root)`로
   지정. 그러면 주소가 이렇게 된다:
   **https://bonhyungu-png.github.io/bridge-guide/**
   (`index.html`이 `webapp/bridge_guide.html`로 넘긴다)

배포 후 README의 "1. 화면" 절 맨 위에 그 주소를 박아 넣을 것.

## 4. 접은 길 — 플러그인 배포 (기록)

`/bridge-guide` 슬래시 명령으로 GUI를 띄우는 방식은 **끝내 동작시키지 못했다.**
MCP로 방향을 바꾼 이유이자, 다음에 같은 함정에 안 빠지기 위한 기록이다.

1. **플러그인 캐시는 `version`으로 키잉된다.**
   `~/.claude/plugins/cache/bridge-guide/bridge-guide/{version}/`에 캐시되고
   `installed_plugins.json`이 **설치 시점의 `gitCommitSha`에 고정**된다.
   `plugin.json`의 version을 안 올리면 push해도 반영되지 않는다.
   **플러그인 내용을 고칠 때마다 version을 반드시 올릴 것.** (현재 0.3.0)
2. **커맨드와 스킬이 같은 이름이면 충돌한다.** 스킬 쪽 frontmatter `name`을
   `bridge-guide-answer`로 바꿔 분리해뒀다.
3. **환경마다 지원 범위가 다르다.** Claude 데스크톱 앱에는 `/plugin`이 없다.
4. **슬래시 명령은 환경 간 표준이 없다.** Claude Code·Cursor·Gemini CLI가
   각각 다른 문법을 쓴다. "모든 환경에서 똑같은 슬래시 명령"은 원리적으로 불가능하다.

MCP는 이 문제가 없다. 명령어가 아니라 **도구**라서, 어디서든 그냥 자연어로
물으면 그쪽 AI가 알아서 집어 쓴다. 2025년 12월 Linux Foundation으로 이관돼
벤더 중립 표준이 됐고 Anthropic·OpenAI·Google·Microsoft·Cursor가 모두 지원한다.

**단, ChatGPT는 예외다.** 원격(HTTP) MCP 커넥터만 지원해서 로컬 stdio 서버는
못 붙인다. ChatGPT에서 쓰려면 웹 GUI를 쓰거나 서버를 HTTP로 감싸 어딘가에
올려야 하는데, 그러면 무료·무설치 전제가 깨진다. 지금은 감수하기로 했다.
