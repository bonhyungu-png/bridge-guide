# bridge-guide 설계 문서

작성 2026-09-07 · 상태: Phase 0 완료

## 1. 목표

교량 안전점검자가 지침서·법령을 헷갈려서 생기는 **판정 오류와 변동성**을 줄인다.

FHWA-RD-01-020(2001)은 현직 점검자 49명에게 같은 교량을 점검시켜, 주요 부재당
평균 4~5개의 서로 다른 등급이 매겨지고 평균 ±1점 이내가 68%뿐임을 측정했다.
문제는 **지침서 접근성이 아니라 해석의 일관성**이다. 검색을 잘 만드는 것으로는
풀리지 않는다.

## 2. 범위

| 항목 | 내용 |
|---|---|
| 전제 | 인터넷 항상 가능. 구독 환경이므로 **토큰 비용은 고려하지 않는다** |
| 대상 | `01. 시설물의 안전 및 유지관리 실시 세부지침(안전점검·진단 편)_교량편` |
| 절 | 1.1 ~ 1.7 |
| 연도 | 2022 / 2023 / 2024 / 2026 |
| 법령 | 참조 5종 20건 (법제처 OPEN API) |
| 제외 | 성능평가 편, 공통편, 건설기준코드 본문 |

## 3. 설계 원칙

1. **사실은 코드가, 문장은 LLM이.** 등급 판정·표 조회·연도 비교·수치 비교는 전부
   파이썬이 한다. LLM이 "0.25는 0.1~0.3 사이니까 b등급"이라고 스스로 계산하지 않는다.
   이유는 비용이 아니라 **재현성**이다. 같은 손상에 항상 같은 등급이 나와야 하고
   그 근거가 표 몇 번 몇 면인지 추적돼야 한다.
2. **출처 없는 사실 문장을 쓰지 않는다.** 모든 사실에 (연도, 표번호, 면수).
3. **정본은 하나.** PDF → 정본 → 지식(빌드 산출물). 파생물을 손으로 고치지 않는다.
4. **내용은 한 곳, 어댑터는 얇게.** 행동 지침은 `skills/bridge-guide/SKILL.md`에만.
5. **어느 창에서 물어도 같은 답.** 모든 경로가 `bridgekb` 한 엔진을 부른다.

### P1 상세

깨진 14건 중 **12건은 콜론/공백 표기 불일치**로 자동 수복 가능하다.

```
본문:   표참조: 표_2단계 : 구조형식별 상태평가결과 결정-1     ← 콜론
파일명: 표_2단계  구조형식별 상태평가결과 결정-1.md            ← 공백 두 칸
```

나머지 **2건은 대응 파일이 아예 없다** (2022년 `표_균열률 산정 방법-1`, `-2`).
이건 추출 누락이므로 원본 PDF를 다시 봐야 한다.

깨진 링크가 하필 **2026년 신설 5단계 종합등급 산정 절차표**에 집중돼 있다.
가장 최근에 바뀌었고 계산이 가장 복잡한 부분이다.

2026년판에 `표1.30 월류(여유고 조사)`가 신설되면서 뒤가 한 칸씩 밀렸다.

## 5. 데이터 계층

```
① 원본 PDF/HWP                        불변. 2015~2026 연도별 폴더
       ↓ 신버전 파이프라인 (2022~2024에 소급 적용 예정)
② 정본/{연도}/text|table/*.md         구조화 + 자동검수
       ↓ build/
③ knowledge/                          빌드 산출물. 손으로 고치지 않는다
```

`연구_1/data/`(구버전 파서, 4개년)와 `DB/정본`(신버전 파서, 2026만)은 **같은 PDF에서
두 번 다르게 뽑은 것**이다. 원본이 둘인 게 아니다. 신버전이 더 낫다(표 75개 중 72개
자동검수 통과)므로 Phase 1에서 이를 2022~2024에 소급 적용해 하나로 통일한다.

## 6. 참조 방식

기존 `표참조:` 규약을 **유지하고 확장**한다. 참조 문자열이 곧 파일명이라
별도 파서 없이 Read/Glob만 쓰는 에이전트가 그대로 따라갈 수 있다.

```
표참조:   표1.11 콘크리트 바닥판 상태평가기준    ← 기존 (유지)
법조참조: 법 제2조                              ← 신규 (법제처 API로 캐시)
기준참조: 건설기준코드 [미해결]                  ← 신규 (링크 없이 표시만)
```

빠져 있던 것은 **검증**이다. `build/00_validate.py`가 전수 검사해 깨진 링크를
리포트로 뽑는다. `DB/검수/`가 이미 표에 대해 하고 있는 방식의 확장이다.

건설기준코드 91건은 지침서 원문에 조항 번호가 없어 링크 대상을 특정할 수 없다.
거짓 링크를 만들지 않고 **미해결 목록**으로 관리한다.

## 7. 질의 흐름

```
질문
 ↓
[LLM] 의도 파악 - 어떤 부재/개념/연도인가
 ↓
[코드] 도구 호출 (횟수 제한 없음)
   concept · anchor · grade · compare · search · law
 ↓
[LLM] 도구가 돌려준 사실만으로 답변 작성
 ↓
답변 + 출처(연도·표번호·면수) + 경고 배지
```

```
bridgekb/           조회 엔진 - LLM을 모른다
  ├ anchor.py       표 조회 (연도 밀림 흡수)          [완료]

  └ surfaces/       웹 UI · MCP 서버                   [Phase 4]
```

### 환경별 필요사항

에이전트 CLI는 **이미 파일 읽기와 셸 실행 능력이 있어서** 지침 파일만 놓으면 된다.
API 직접 호출은 **도구 스키마와 실행 루프**를 우리가 제공해야 한다.

| 환경 | 부류 | 필요한 것 | 상태 |
|---|---|---|---|
| Claude Code | A | `CLAUDE.md` + `commands/` + `skills/` | 완료 |
| Gemini CLI | A | `GEMINI.md` + `gemini-extension.json` | 완료 |
| Cursor | A | `.cursor/rules/*.mdc` | 완료 |
| Codex | A | `AGENTS.md` | 완료 |
| Anthropic/Gemini/OpenAI API | B | `providers/*.py` + 도구 스키마 | Phase 4 |
| 웹 UI | B | `surfaces/web/` (FastAPI + 단일 HTML) | Phase 4 |
| MCP 클라이언트 | B | `surfaces/mcp.py` | Phase 4 |

A군은 포인터 파일뿐이고, B군은 `providers/base.py`에 스키마와 루프를 한 번 쓰면
나머지는 SDK만 갈아끼운다.

## 10. 답변 품질 기준

비용 최적화 대신 이 기준으로 평가한다.

| 기준 | 내용 |
|---|---|
| 출처 필수 | 모든 사실 문장에 (연도, 표번호, 면수) |
| 경고 우선 | 분류 함정·표번호 밀림은 답변 맨 앞에 배지로 |

| 일치성 | 어느 환경에서 물어도 같은 도구 결과 |
